01 / 项目背景与挑战

海外制造基地的工业 AI、知识检索与智能运维需要统一的私有化算力底座。核心挑战是训练与推理的资源竞争：模型显存需求、在线响应与批量训练负载不同，需要规划 GPU 资源池、隔离工作负载并建立可验证的模型发布流程。

02 / 工程实施与个人职责

计算资源为 4 台 Dell R760xa、16 张 NVIDIA L40S 与 3 台 Dell R660 控制节点。以 Linux、Docker、Kubernetes 和 NVIDIA GPU Operator 管理资源，承载 Qwen2.5-32B、14B、Embedding、Rerank 及视觉模型服务。

我在项目中的贡献：

  • GPU 资源池规划：围绕模型显存、训练任务与在线推理划分资源，明确训练推理隔离及昼夜调度方案；自动切换能力按验证进度推进。
  • 模型部署与推理链路：HAProxy → Envoy → Inference Router → vLLM → CUDA/GPU，关注模型加载、显存不足、请求超时与服务恢复。
  • 训练与发布流程：数据准备 → SFT/LoRA → Checkpoint → 模型评测；发布前执行模型验证与压力测试，按灰度方案发布并保留回滚版本。
  • 运维保障采用 Prometheus、Grafana 与 DCGM Exporter，围绕 GPU 利用率、显存、温度和服务状态排障，按测试记录验证并发、延迟及恢复能力。

03 / 成果验证与工程复盘

平台围绕私有化 GPU 资源池组织模型服务、训练链路与运维保障。验收关注模型可用性、训练产物、监控覆盖及发布回滚记录；吞吐、延迟与并发上限需经专项压力测试确认，昼夜自动调度及自动化恢复不作为已完成成果。工程复盘重点是先明确资源边界，再用可重复测试验证稳定性，避免将架构方案等同于生产能力。
